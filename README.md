# SQL 财务分析工单台 v2

面向财务人员的 SQL 练习环境：**真 SQLite 引擎 + 一套带脏数据的模拟账套 + 13 道真实工单**。

和 v1 最大的区别不是界面，是这四件事：

| | v1 | v2 |
|---|---|---|
| 执行引擎 | 自研 JS 解析器，语法支持有限、行为不完全等同数据库 | **SQLite 1.13 (WASM)**，和你在公司用的数据库同一套 SQL 语义 |
| 数据 | 5 部门 / 11 科目 / 几百行，干净整齐 | **7 张表 / 26,000 行**，故意留 6 类脏数据 |
| 窗口函数 | 不支持 | 支持 LAG / ROW_NUMBER / SUM OVER / 移动平均 |
| 题目形态 | 语法示例（`SELECT * FROM t WHERE ...`） | **业务工单**：总监问一句话，你自己拆成 SQL，系统自动对答案 |

## 数据里埋了什么

真实财务表不是干净的。这套数据复刻了最常见的六种脏：

1. **重复导入的单据**——同一单据被导入两次，让你在账表核对时差出 2,500 万
2. **一客多码**——同一个客户建了两个编码，销售额被拆成两半
3. **名称带尾随空格**——`GROUP BY` 不 TRIM 就会多出一组
4. **两种日期格式**——`2026-10-05` 和 `2026/10/05` 混存，`date()` 会静默返回 NULL
5. **退货是负数**——不处理就会把收入算高
6. **折扣为 NULL**——不用 `COALESCE(discount,0)` 会让整行金额变成 NULL

另外埋了两个业务事件，需要你自己用 SQL 挖出来：

- 华东 4 个客户 10 月起折扣从 7% 拉到 35%+，毛利率直接打穿成负数（T13 就是让你定位它们）
- 客户服务部 2026 年管理费用预算被砍 45%，实际必然超支（T08）

## 主题切换（深色 / 浅色）

两个页面右上角都有一个圆形按钮，点一下就在深色和浅色之间切换：

- 选择存在 `localStorage` 的 `sqllab-theme`，**刷新、关浏览器都不丢**，练习台和计划页共用同一个值，切一处两处一起变
- 想在链接里直接指定主题（方便分享或投屏）：在地址后加 `?theme=light` 或 `?theme=dark`
- 用 `?theme=` 打开后，只要手动点过一次切换，参数就会自动从地址栏移除，之后以本地记忆为准

配色全部走 CSS 变量（`--bg`、`--panel`、`--tx`、`--code-bg` 等），定义在 `index.html` 和 `plan.html` 的 `:root` 里，浅色覆盖写在 `html[data-theme="light"]` 块内。要改配色只动这两块，不要去改具体选择器。当前两套主题的正文、表格、代码区、提示色对比度都过了 WCAG AA（≥4.5:1）。

## 45 天学习计划

`plan.html` 是配套的学习路线，面向「语法已经忘得差不多、每天只有 30-60 分钟」的情况：

| 阶段 | 时间 | 内容 | 产出 |
|---|---|---|---|
| P0 | Day 1 | 熟悉数据、不怕报错 | — |
| P1 | Day 2-8 | SELECT → WHERE → ORDER → GROUP BY → HAVING | 能用真实表回答 5 个业务问题 |
| P2 | Day 9-15 | DISTINCT / TRIM / 数据体检思维 | T01-T03 |
| P3 | Day 16-23 | NULL / 日期 / CASE / JOIN 入门 | T04-T06 |
| P4 | Day 24-31 | 子查询 / 三表 JOIN / 账龄 | T07-T09 |
| P5 | Day 32-41 | 窗口函数：LAG / SUM OVER / ROW_NUMBER | T10-T12 |
| P6 | Day 42-45 | 行转列 + 综合工单 | T13 |

每天分三块：**学**（语法点，含可复制的例句）、**做**（具体动手动作）、**验收**（怎么算过关）。每个阶段最后一天是「回炉日」——按时完成就用来重做旧题，落后就用它补进度，不会因为掉队一天就放弃。

打卡进度存在浏览器 localStorage，换设备不同步。

### 答案与解析

每天底部有一个可折叠的「参考答案 + 解析」，**默认收起**，先自己写、卡住了再展开：

- 40 天有可直接运行的 SQL（折叠区里点一下就能复制到练习台跑）
- 13 道工单题（T01-T13）直接引用练习台的官方答案，不会出现两套口径
- 4 个回炉日（Day 14 / 23 / 31 / 40）只有解析和自查清单，没有新答案
- 每条解析都写清三件事：为什么这么写、常见错法长什么样、正确结果应该是多少

右上角「展开全部答案」可以一次性铺开，适合复习时对照。

**所有答案都跑过一遍。** `node test/verify-plan.mjs` 会把 45 天里的每一条 SQL 在真实账套上执行，
输出行数和前几行，最后给出通过/失败统计。当前状态：77 条成功、2 条预期报错（故意写的错误示范）、0 条失败。

写这套解析时对着真实数据校出 6 处原计划的口误，已在 `plan-data.js` 里改正：
月份分组不加 `REPLACE` 会得到 44 个假月份、`SUM` 加不加 `COALESCE` 结果相同（差异在 `AVG`）、
`COUNT(DISTINCT` 看不出空格问题、2026-10 收入是 4.98 亿而非 4.4 亿、账表差额是 2,984 万而非 2,585 万、
"一客多码"不是靠行数差发现的。

数据是**运行时生成**的，不是预置的数据库文件——所以整个目录只有 60KB，加载时约 1 秒建好 26,000 行。

## 分组专项（drill.html）

Day 06 学了 GROUP BY 之后如果觉得不够，去做这个。8 道题全部围绕"分组"这一个动作，难度递进：

| # | 题目 | 真正考什么 |
|---|---|---|
| 1 | GROUP BY 到底在做什么 | 输出行数 = 分组键有几个不同值 |
| 2 | SUM 里有负数：退货要不要算 | 负数是业务事实，不是脏数据 |
| 3 | 分组前先洗分组键：月份 | 不 REPLACE 斜杠，22 个月变 44 个 |
| 4 | HAVING：筛的是组，不是行 | 聚合条件写进 WHERE 必然报错 |
| 5 | 两维分组：GROUP BY 两列 | 分的是"组合"，不是两列分别分 |
| 6 | COUNT(*) 的陷阱：行数不是单数 | 26,284 行 vs 8,680 单，差 3 倍 |
| 7 | 一客多码：按名字还是按编码 | 128 个编码 vs 120 个名称 |
| 8 | 每组第一名：GROUP BY 给不了的东西 | 必须"先聚合、再排名"两层 |

每题都是「学 / 做 / 验收」三段，答案默认收起。打卡进度存 localStorage（键 `sql-drill-gb-done`）。

**答案全部验证过。** `node test/verify-drill.mjs` 会执行 17 条 SQL（其中 1 条是故意写错的示范），
并核对解析里出现的 36 个数字，例如「耗材销量 80,504」「退货 424 行 / -3,573 件」
「远方教育合并后 14,492.5 万」。当前状态：16 条成功、1 条预期报错、0 失败、36 项断言全过。

写这套题时踩到一个值得记的坑：想做"每区域第一名"，我最初用相关子查询把内层的 MAX
关联到外层分组列，SQLite **不报错，直接返回 0 行** —— 它没法从 HAVING 里的派生表反向关联
外层列。最后改成「聚合两次再 JOIN 回去」的老写法和 `ROW_NUMBER()` 两个版本，两种都收在答案里。

## 部署到 GitHub Pages

1. 把 `index.html` 和 `src/` 整个目录推到仓库 `main` 分支

## 怎么加题

在 `src/tasks.js` 的 `TASKS` 数组里加一个对象：

```js
{
  id: 'T14',
  stage: '窗口函数',            // 左侧分组标题
  title: '按客户算移动三个月均值',
  scene: '业务方想平滑季节性波动……',   // 谁在问、为什么问
  ask: '输出客户、月份、收入、近三月均值，按客户月份排序。',
  cols: ['客户', '月份', '收入', '三月均值'],   // 期望输出列（顺序要一致）
  hint: 'AVG(...) OVER (PARTITION BY ... ORDER BY ... ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)',
  answer: `SELECT ...`          // 参考答案，校验就是拿它跑出来的结果做对比
}
```

校验逻辑是**按值和行序逐格对比**（数值容差 0.02），所以：

- 参考答案必须自带确定的 `ORDER BY`（金额相同的行要加 `cust_code` 之类兜底，否则行序不稳）
- 输出列顺序要和 `cols` 一致

加完题不用改别的，左侧导航会自动出现。

## 已知限制

- 数据是内存库，刷新即重置（练习够用，不需要持久化）
- 只支持 SQLite 方言。`DATE_FORMAT()`、`IFNULL()` 这类 MySQL 函数不通——SQLite 用 `strftime()`、`COALESCE()`
- 校验是"结果一致"而非"写法一致"，解法不同但结果对也算通过
